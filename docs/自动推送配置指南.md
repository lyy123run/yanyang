# 每日自动推送配置指南（微信 + 邮箱）

## 一、整体架构（为什么要这样设计）

本系统部署在 PythonAnywhere 免费版，实测该平台有两个限制：

1. **没有定时任务**（Scheduled tasks / Always-on tasks 均为付费功能）；
2. **出站网络受限**：无法直接访问微信/Server酱 API 和 SMTP 服务器（实测 `sctapi.ftqq.com`、`smtp.qq.com` 均连接失败）。

因此自动推送拆成两段，全部可免费实现：

```
[PythonAnywhere 上的 Django 系统]                [GitHub Actions 定时任务，免费]
  令牌接口 /push/cron/<token>/   ── 每天定时拉取 ──►  ① Server酱 → 微信收到消息
  （返回今日训练+疲劳状态 JSON）                      ② SMTP    → 邮箱收到邮件
```

- 系统侧只负责“入站”：提供带密钥保护的接口，返回真实报文；
- 外发由 GitHub Actions 完成（GitHub 服务器可正常访问外网，公开仓库 Actions 免费）。

## 二、需要准备的东西（均免费）

| 物料 | 用途 | 获取方式 |
|---|---|---|
| GitHub 账号 | 运行定时任务 | github.com 注册 |
| Server酱 SendKey（可选，要微信推送才需要） | 消息推到微信 | 微信扫码登录 sct.ftqq.com，复制 SCT 开头的 SendKey；免费会员 5 条/天 |
| 邮箱 SMTP 授权码（可选，要邮件推送才需要） | 发邮件 | 以 QQ 邮箱为例：设置 → 账号 → 开启 SMTP，生成授权码（不是登录密码） |

## 三、系统侧：设置令牌

在 PythonAnywhere 的环境变量（或 .env 文件）中设置：

```
CRON_PUSH_TOKEN=换成一串你自己的随机字符串，例如 myrun2026abcXYZ
```

PythonAnywhere 免费版可在 WSGI 文件中加入：

```python
import os
os.environ["CRON_PUSH_TOKEN"] = "myrun2026abcXYZ"
```

重新加载（Reload）站点后，登录系统进入“消息推送”页，会显示令牌接口地址，形如：

```
https://liuyanyang2026.pythonanywhere.com/push/cron/myrun2026abcXYZ/?username=runner
```

浏览器直接打开能看到 JSON 报文，即系统侧配置成功。错误令牌会返回 400。

## 四、GitHub 侧：创建仓库与定时任务

1. 在 GitHub 新建一个仓库（公开即可，免费），把本项目代码推上去（仓库里已含
   `.github/workflows/daily_push.yml` 和 `scripts/daily_push_job.py`）。
2. 仓库页面 → **Settings → Secrets and variables → Actions → New repository secret**，
   依次添加以下密钥（只填你需要的渠道）：

| Secret 名 | 填什么 | 是否必填 |
|---|---|---|
| `CRON_URL` | 第三步得到的完整令牌接口地址 | 必填 |
| `SERVERCHAN_SENDKEY` | Server酱的 SCT SendKey | 微信推送必填 |
| `SMTP_HOST` | 如 `smtp.qq.com` | 邮件推送必填 |
| `SMTP_PORT` | 如 `465` | 邮件推送必填 |
| `SMTP_USER` | 发件邮箱地址，如 `2582675506@qq.com` | 邮件推送必填 |
| `SMTP_PASSWORD` | 邮箱 SMTP 授权码（不是登录密码） | 邮件推送必填 |
| `MAIL_TO` | 收件邮箱（可与发件邮箱相同） | 邮件推送必填 |

3. 仓库页面 → **Actions** 标签 → 选择 `每日训练推送` 工作流 → 点击 **Run workflow**
   手动触发一次，微信和邮箱应立即收到消息。之后每天北京时间约 06:50 自动执行
   （cron 为 UTC 22:50，可在 yml 文件中修改）。

> 注意：GitHub 官方文档说明，免费公开仓库的计划任务在仓库连续 60 天无活动后可能被自动暂停，
> 期间只要有提交或手动触发即可恢复。演示前建议手动 Run 一次确认。

## 五、本地/付费主机的替代方案（不依赖 GitHub）

如果以后换到能访问外网的付费云服务器，可直接用系统自带的管理命令，配合系统 crontab：

```bash
# 每天 6:50 给所有开启推送的用户发送
50 6 * * * cd /路径/marathon_trainer && /虚拟环境/bin/python manage.py daily_push
```

也可只给指定用户：`python manage.py daily_push --username runner`。

## 六、演示时怎么讲（答辩口径）

1. 打开“消息推送”页，展示令牌接口地址，浏览器打开显示真实报文 JSON（今日训练 + 疲劳指标）；
2. 在 GitHub Actions 点 **Run workflow**，现场展示微信/邮箱收到同内容消息；
3. 说明架构选择：免费平台不支持定时任务和出站访问，故采用“系统提供数据 + 外部定时任务外发”的
   解耦设计，迁移到付费服务器后只需一条 crontab 即可，业务代码无需改动；
4. 未配置真实密钥时，系统所有渠道自动进入 dry_run 模式：完整报文打印在后端日志，功能链路可完整演示。
